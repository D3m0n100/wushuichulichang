5. 连接竞争场景

前端多个页面同时轮询同一个 PLC 时，会争抢连接池中的连接：

来源调用轮询间隔
plc-debug.htmlGET /api/plc/b1/overview3000ms（默认）
前端 B1.vueGET /api/plc/b1/overview3000ms
前端 Dashboard.vueGET /api/plc/b1/overview5000ms
前端 AlarmPage.vueGET /api/plc/b1/overview轮询
前端 ProcessControl.vueGET /api/plc/b1/overview轮询

当多个页面同时轮询时，3 个连接要被 2-5 个并发请求争抢，可能导致：

  • 请求排队等待连接（borrowObject 阻塞）
  • 5秒超时后报错 Failed to read B1 PLC tags

二、优化方案

方案一：S7-200 SMART 真正实现连接池化

优先级：高 改动量：中

当前 AbstractS7ConnectionPool 每次都新建连接再销毁，完全浪费。应该像 B1 那样用 Apache Commons Pool2 管理连接：

// 当前（每次新建）
public PlcConnection borrowConnection() {
    return new PlcDriverManager().getConnection(url);  // 新建TCP连接
}

public void returnConnection(PlcConnection connection) {
    connection.close();  // 立即销毁
}
// 优化后（复用连接）
private final GenericObjectPool<PlcConnection> pool;

public PlcConnection borrowConnection() {
    return pool.borrowObject();  // 从池中借出
}

public void returnConnection(PlcConnection connection) {
    pool.returnObject(connection);  // 归还到池中
}

效果：减少 90% 的 TCP 连接建立/销毁开销，每次请求节省 50-200ms。

方案二：S7-200 SMART 批量读取

优先级：中 改动量：大

当前每个标签单独发一次 ReadArea，读10个标签 = 10次 PLC 通信。应该合并为一次：

// 当前（逐个读取）
for (String tagCode : tagCodes) {
    readArea(client, area, 0, byteOffset, buffer);  // 每个标签一次通信
}

// 优化后（批量读取）
// 将连续地址的标签合并为一次 ReadArea 调用
// 例如 DB1.DBX16.0~DB1.DBX16.4 可以一次读取 1 字节

效果：减少 PLC 通信次数，降低网络延迟。

方案三：增大连接池容量

优先级：高 改动量：小

当前所有池都是 maxTotal=3，前端多个页面同时轮询时会排队。建议：

// S7-200 SMART 池
config.setMaxTotal(5);    // 3 → 5
config.setMaxIdle(3);     // 2 → 3

// B1/H1/M3 池
config.setMaxTotal(5);    // 3 → 5
config.setMaxIdle(3);     // 2 → 3

效果：支持更多并发请求，减少超时。

方案四：前端轮询优化

优先级：低 改动量：中

当前多个页面各自独立轮询，同一个 PLC 被请求多次。可以：

  • 方案A：后端增加缓存层 — overview 结果缓存 1-2 秒，多个前端请求共享同一份数据
  • 方案B：前端共享轮询 — 使用一个全局 store，只发一次请求，多个组件共享数据

三、优先级建议

优先级方案改动量效果
🔴 高方案一：连接池化中减少 90% 连接开销
🔴 高方案三：增大池容量小减少超时
🟡 中方案二：批量读取大减少 PLC 通信次数
🟢 低方案四：前端轮询优化中减少总请求数

四、注意事项

  • 关闭 plc-debug.html 后不会残留连接 — HTTP 请求是无状态的，关闭页面后所有连接立即释放
  • S7-200 SMART 的 TSAP 轮转机制 — 14个候选地址按顺序尝试，失败后切换到下一个，成功后记住该地址
  • S7-1200 的 PLC4X 连接 — 支持真正的连接池化和批量读取，效率远高于 S7-200 SMART
  • 脉冲信号 vs 持续信号 — 粗格栅等设备使用脉冲信号（写true→等待→写false），B1/H1/M3 使用持续信号（写1等待写0）
