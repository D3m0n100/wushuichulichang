# 项目导读

## 从哪里开始

| 关注点 | 入口和联系 |
| --- | --- |
| 页面与导航 | `frontend/src/main.js` 挂载 Vue。入口布局在 `App.vue`，路由及登录守卫在 `router/index.js`，菜单和工艺座舱导航在 `components/layout`。看板、流程、工艺参数、设备页和历史页都在 `views`。 |
| 认证与会话 | 前端 `api/request.js` 与 `utils/authSession.js` 处理请求和会话。后端查看 `LoginController`、`JwtInterceptor`、`JwtUtil`、`PasswordScheduleService`。优先对照补丁和 JAR 参考代码。 |
| PLC 与工艺设备 | 从对应设备 Vue 页面追踪请求至后端 `controller`，继续读对应 `service`、连接池和共享基类。`frontend/public` 的两份设备接口对照 CSV、PLC 分析文档和联调页面提供映射及背景。 |
| 三维场景和可视化 | Babylon.js 模型加载和设备节点关联分布在 Vue 设备页面、`components/ModelViewer.vue` 和 `utils/h1ModelDevices.js`。模型索引包含实际文件、静态文件名引用、节点名、网格和动画数量。 `source_literal_references` 记录直接匹配到文字的前端源文件，动态引用需继续读代码。 |
| 历史与报警 | 从 `History.vue`、`InflowMonitor.vue`、`AlarmPage.vue` 和 `GlobalAlarm.vue` 进入。后端 `MonitorDataController`、`InflowHistoryController`、`PointHistoryController` 和 `DeviceFaultController` 对应监测查询及故障。 |
| 数据库 | 后端 `MonitorPersistenceScheduler`、`MonitorPersistenceService` 与 `MonitorJdbcRepository` 连接采集、持久化和查询。表结构、基础点位和迁移位于 `backend/database`，存储规则见 [数据库说明](数据库设计与数据存储逻辑说明书.md)。 |
| 生产运行 | `backend/application-prod.example.yaml` 是配置样例，`backend/scripts` 包含 Windows 服务、守护、数据库初始化、备份和诊断脚本。 `docs/使用说明.txt` 描述的是已组装的 Windows 生产包，其中提到的控制中心 EXE 和内置 Java 运行时未随原 Git 仓库提交。 |

## 前端与后端代码的范围

前端是 Vue 3 / Vite，配合 Vue Router、Element Plus、ECharts 和 Babylon.js 等。前端开发模式通过 Vite 代理转发 `/api`。Spring Boot 2.7.18 后端负责服务接口、PLC 数据和 MySQL 监测存储。JAR 内的 Maven 元数据记录 Java 目标版本为 8，现有生产说明使用 Java 17 运行时。

实际部署使用 `backend/waterfactoryceshi.jar`。原仓库只提交了部分 Java 源码补丁。 `backend/reference` 给缺少原始源码的类提供可阅读的反编译代码，并保留了 JAR 提供的 Maven 依赖清单。生产配置以部署环境和配置样例为准。原始 JAR 的内置配置含数据库密码字面值，运行时应使用外部配置提供实际凭据。
